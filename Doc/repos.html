MIvoter.org repositories & projects

Charles Roth
Last updated: Sept 8, 2026.

I. Introduction
MIvoter.org is actually a combination of several distinct project repositories.  This division allows us to more easily parcel out pieces to different developers, and support different versions during development.

The overall project is a classic "LAMP" stack, currently running on:

  • AlmaLinux 8
  • PHP 8.2.3 with Smarty 5.4 (and Twig 3.8)
  • MySQL 8.0.45
  • Python 3.9 (for just a few data management scripts)
Currently, everything lives on a single server.  The MySQL database, in particular, is locked-down to only allow access from the local server -- no network access at all. 

However, we will need to find ways to scale up the overall operation, as we get nearer to the election. 

(We are looking at a "lift and shift" migration to an AWS EC2 environment, but the goal is to change as little as possible in the process.)

II. Project Repos

  1. mivoter.org.  The actual UI for the voting guide.
  2. address.mivoter.org.  A stand-alone web service for matching voter addresses.
  3. editor.mivoter.org.  The overall data editor, for volunteer curators and CDPs.
  4. Data Manager (editor.mivoter.org/dm).  The "officials" (incumbents) and "candidates" editor.
  5. Alfred.  A library of low-level PHP utilities, that are used throughout mivoter.org.
  6. feedback.editor.mivoter.org.  Site feedback manager, and voter log graphing.
  7. ElectionImport.  A large collection of PHP (and some Python) scripts dealing with data import from a variety of sources.

IV. address.mivoter.org
Repo: git@github.com:/mivoter/AddressService.git
Location: /home/address/AddressService

  1. In 2024, we used the google address tool to rapidly identify a voter's address -- they could just start typing their address, and quickly get a pull-down list of matching locations.

    Unfortunately, there were often serious mismatches between google's address data, and the official State of Michigan data.

    So, we wrote our own.  It starts with the data from Michigan's "street index", which is the master table that maps sections of streets across the state, into the various district codes (us congress, state senate, state house, county, city, township, village, school board, etc.).

    It then "mutates" the street names for better matching (e.g. "N" and "North").

  2. The service itself simply takes a partial address, and quickly returns a list of possible matches.  It's up to javascript in the actual mivoter.org UI to deal with them.
  3. This service uses only a few tables from the MySQL database, and does not write anything.  So it is also an easy candidate for splitting off for load-balancing.

IV. editor.mivoter.org
Repo: git@github.com:/wchasroth/azure_v4.git
Location: /home/miv_ed_v4/AzureV4

  1. The editor site itself is a frameset (yes, an ancient construct, but in this case still a useful tool) that handles a variety of different "kinds" of data editing.  Some of the editing is built-in to this project; others are links to different URLs that are implemented in separate project repos.
  2. We use Google Auth for authentication -- much easier than rolling our own.
  3. Authorization for the different "kinds" of editing is handled by this editor, and we use encrypted cookies to validate the authorization, especially for the tasks that are handled by different project repos.
  4. As such, this is the most potentially vulnerable project, since it can write to everything in the MySQL database.

V. Data Manager
Repo: git@github.com:/wchasroth/editorV4.git
Location: /home/miv_dm_v4/EDV4

  1. This is the biggest single part of the "editor", as it manages all of the data for officials (incumbents) and candidates.  It in turn has a left frame (explodable list of counties etc.) and a right frame (panel for editing selected jurisdiction's offices).
  2. Like the editor, it too is a potentially vulnerable area, although it uses the encrypted cookie supplied from editor.mivoter.org to determine authorization.
VI. Alfred
Repo: git@github.com:/wchasroth/Alfred.git
  1. Alfred (think Bruce Wayne's butler) is a library of support classes for all of our political infrastructure work.  E.g. an extended version of PHP's PDO MySQL interface, a cookie-handling utility class, etc.
  2. Alfred is published via packagist, and is freely downloadable via PHP's composer.

VII. feedback.editor.mivoter.org
Repo: git@github.com:/mivoter/mivoter-feedback.git Location: /home/miv_fb_sta/MIV24

  1. This project combines two different tools -- the feedback manager, and the voter log graphing tool.  They are in turn linked to from the master editor.mivoter.org.
  2. Will Jaynes is the author of this project.
  3. It is potentially vulnerable, although it only (intentionally) writes to the 'feedback' table.

VIII. ElectionImport
Repo: git@github.com:/wchasroth/ElectionImport.git

  1. Collection of a wide variety of scripts for handling data import (some old, some new).
  2. No internet exposure: these are all for dealing with data internally, on the server.
